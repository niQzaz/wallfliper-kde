# Этап 0 — проверка окна на KWin (Plasma 6 Wayland)

Цель: выбрать тип окна по фактическому поведению. Карусели и бэкенда обоев здесь нет.
Прототип ничего не меняет в настройках KDE и не запускает swww/mpvpaper.

## 0. Подготовка (без sudo, ничего не меняет)

```
cd <каталог wallfliper-kde>
./stage0/check_env.sh            # или ./stage0/check_env.sh --with-dnf
```
Пришлите вывод целиком. Если `python3-pyside6` или `layer-shell-qt` не установлены — остановитесь:
я назову точную команду `sudo dnf install ...`, выполнять её будете вы сами, после своего подтверждения.

Запускайте **системным** `python3` (`/usr/bin/python3`), не из venv/conda и не с pip-PySide6.

## Безопасность
- Окно само закрывается через 90 с (`--timeout N`, `0` — отключить).
- Если окно «захватило» клавиатуру и не закрывается: Ctrl+Alt+F3 → `pkill -f stage0/proto.py` → Ctrl+Alt+F1/F2
  (или вторым запуском той же команды из другого терминала/по горячей клавише).

## Режимы
| режим | что это |
|---|---|
| `layer` | layer-shell, Overlay, Exclusive-клавиатура (копия оконного блока оригинала) |
| `layer-active` | то же + `wantsToBeOnActiveScreen` (если layer-shell-qt его знает) |
| `plain` | обычное безрамочное окно размером с экран |
| `plain-fullscreen` | обычное безрамочное окно, полноэкранное |

Запуск: `python3 stage0/proto.py --mode <режим>` (для plain можно `--screen cursor|primary|none`).
Логи: терминал + `~/.cache/wallfliper-kde-stage0/<режим>.log` (JSON-строки).

## Тесты (для каждого режима; в таблицу пишите ✓ / ✗ / «н/п» и комментарий)

| № | Что делать | На что смотреть |
|---|---|---|
| T1 | Запустить из терминала | Окно появилось? Ошибки в терминале (`qml-warning`, `load-failed`)? Панель по центру, фон прозрачный, нет чёрных прямоугольников/мерцания |
| T2 | Заранее откройте любое окно на весь экран/максимизированное, затем запустите прототип | Панель видна **поверх** окон? А поверх панели Plasma (taskbar)? |
| T3 | Сразу после появления, **не кликая**, нажмите несколько клавиш | Счётчик «last key» растёт? В логе есть `key`? (`window-active true`, `scope-activeFocus true`) |
| T4 | Нажать Esc | Закрылось сразу? В логе `esc-quit`, затем `exit code=0` |
| T5 | Запустить, кликнуть в пустое место | Закрылось (`click-away`)? Клик по самой панели не закрывает |
| T6 | После закрытия: `pgrep -af stage0/proto.py` и сразу запустить снова | Процессов не осталось; повторный запуск работает |
| T7 | Запустить, во втором терминале выполнить ту же команду | Первое окно закрылось (`signal-quit`), второй процесс вышел с сообщением о toggle |
| T8 | Meta+D при открытом окне (потом Meta+D ещё раз) | Окно исчезло/осталось? Вернулось ли? Есть ли отклик в клавиатуре после этого? |
| T9 | Позиция на мониторе (нужно ≥2 монитора, иначе «н/п»): активируйте окно на втором мониторе, курсор там же, запустите **по горячей клавише** (см. ниже) | На каком мониторе появилось окно; совпадает ли со строкой `screen` на панели; для plain — `set-screen` и `cursor` в логе |
| T10 | Масштаб (если у вас не 100 %): строка `dpr`, резкость текста, размер окна = размер экрана? | `window` на панели vs `screen` |
| T11 | Задержка: строка `first-frame` в логе | время в мс от старта процесса |

Для plain-режимов отдельно отметьте: окно поверх других при клике на другое окно (StaysOnTop реально работает?),
есть ли рамка/тень/заголовок от KWin, не появилась ли запись в панели задач.

## Горячая клавиша (T8/T9) — ручная настройка, делаете вы
Я ничего в KDE не менял. Если разрешаете, сделайте сами (названия пунктов могут чуть отличаться по версии):

1. System Settings → Keyboard → Shortcuts → **Add New → Command or Script**.
2. Команда: `/usr/bin/python3 /ПОЛНЫЙ/ПУТЬ/wallfliper-kde/stage0/proto.py --mode layer`
3. Назначьте сочетание, например Meta+Shift+W (проверьте, что оно не конфликтует).
4. Проверки: (a) сочетание открывает окно, когда фокус в другом приложении; (b) **повторное нажатие при открытом окне**
   закрывает его (если Exclusive-клавиатура мешает доставке — это важный результат); (c) нет дубликатов процессов (`pgrep -af proto.py`).
5. После тестов удалите это сочетание тем же способом (Shortcuts → ваша запись → Удалить).

Для остальных режимов поменяйте `--mode` в команде.

## Что прислать
Вывод `check_env.sh`, заполненную таблицу и четыре файла из `~/.cache/wallfliper-kde-stage0/`
(или хотя бы строки `env`, `screen`, `cursor`, `qml-warning`, `load-failed`).

## Повторный тест после исправления (ревизия 2)
Исправлены ошибки `plain`/`plain-fullscreen` при завершении (см. отчёт). Проверьте именно их:

```
python3 stage0/selftest.py                          # без Qt, 20 проверок, ожидается ALL CHECKS PASSED
rm -f ~/.cache/wallfliper-kde-stage0/plain*.log     # чтобы в логах были только новые запуски
python3 stage0/proto.py --mode plain                # затем Esc
python3 stage0/proto.py --mode plain-fullscreen     # затем Esc
python3 stage0/proto.py --mode layer                # контроль: Esc
grep -c qml-warning ~/.cache/wallfliper-kde-stage0/*.log
grep -h teardown   ~/.cache/wallfliper-kde-stage0/*.log
```
Ожидание (гипотеза, пока не проверена в вашей сессии): в терминале нет `TypeError` и `ValueError`,
в каждом логе есть `exit code=0`, затем `teardown engine deleted` и `teardown signal notifier deleted`,
`qml-warning` = 0. Если `qml-warning` не 0 — пришлите строки, теперь они не теряются.
